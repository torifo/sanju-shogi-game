# 三重将棋 オンライン対戦（招待リンク）設計書

- 日付: 2026-11-02
- 状態: 暫定
- 前提: `2026-10-31-sanju-shogi-design.md`（ルール・画面・構成）。ローカル対戦はそのまま残す。

## 1. 概要

GitHub Pages のまま、離れた 2 人が招待リンクで対戦できるようにする。
サーバーは持たず、接続の仲介（シグナリング）だけを Trystero の Nostr 方式（公開リレー、登録不要）に任せ、指し手はブラウザ同士の WebRTC で直接やり取りする。

### 決めたこと

| 項目 | 決定 |
|---|---|
| つなぎ方 | 招待リンク（部屋を作った人がリンクを相手に送る）。ランダムマッチはやらない |
| 仲介 | `@trystero-p2p/nostr`（公開 Nostr リレー）。TURN サーバーは使わない |
| 人数 | 1 部屋 2 人。3 人目は「満員」と表示して入れない |
| 先手・後手 | 部屋を作る人が「先手 / 後手 / ランダム」を選ぶ |
| 秘密配置 | 各自の端末で同時に配置。ハッシュを先に送り合ってから中身を公開する（コミット・リビール） |
| 指し手の検証 | 受け取った側も既存の `core` で合法か確かめる。食い違ったら対局を止める |
| 待った | 相手の承認が要る |
| 切断 | 盤面は両者の端末に残る。同じリンクを開き直せば続きから再開 |

### やらないこと

ランダムマッチ・待合室、観戦、チャット、持ち時間、TURN による中継、改造クライアントによるずるの防止（友達同士で遊ぶ前提）。

## 2. 招待リンク

```
https://torifo.github.io/sanju-shogi-game/#room=<roomKey>
```

- `roomKey` は暗号学的乱数 128 bit を base64url にした 22 文字。
- `#` 以降はサーバーに送られないので、GitHub Pages のアクセスログにも残らない。
- Trystero には `appId: 'sanju-shogi-game'`、部屋名 = `roomKey` の SHA-256 の先頭 16 文字、`password` = `roomKey` を渡す。リンクを知っている人だけが接続でき、リレーには部屋名しか見えない。
- 部屋を作った画面には「リンクをコピー」と、使える端末では共有ボタン（Web Share API）を出す。

## 3. 流れ

```
タイトル →「オンライン対戦」→ 部屋を作る（先手/後手/ランダムを選ぶ）
  → 待機画面（リンクを表示）……相手がリンクを開く → 接続
  → 両者が自分の端末で配置（相手の駒は表示しない。交代画面はない）
  → 確定するとハッシュを送信。相手の確定を待つ
  → 両者のハッシュがそろったら中身を送信 → 照合 → 公開演出 → 対局
  → 終局（詰み・投了・千日手）→ 「タイトルへ」
```

相手側はリンクを開くと「接続しています」と出て、つながれば同じ配置画面に入る。

## 4. メッセージ

すべて 1 つのアクション `msg` で送り、`type` で分ける。受け取ったメッセージは形を検証してから使う（形が違えば捨てる）。

| type | 中身 | 送る側・時機 |
|---|---|---|
| `hello` | `protocol: 1`, `role: 'host' \| 'guest'`, `layers`, `resume?: SyncState` | 接続直後に両者 |
| `assign` | `hostColor: Color` | host が hello を受けた後（ランダムなら host の端末で決める） |
| `commit` | `hash`（SHA-256 hex） | 自分の配置を確定したとき |
| `reveal` | `assignment: number[]`, `salt` | 両者の commit がそろった後 |
| `move` | `ply`, `move`（`encodeMove` の文字列） | 自分の手を指したとき |
| `undo-request` / `undo-reply` | `ply` / `ply, accepted` | 待ったの申し入れと返事 |
| `resign` | `color` | 投了 |
| `sync` | `SyncState` | 再接続時（下記） |
| `full` | なし | 3 人目に返す |
| `error` | `reason` | 食い違いなどで対局を止めるとき |

- `hash = SHA-256(JSON.stringify({ assignment, salt }))`。`salt` は 128 bit の乱数。
- reveal を受けたら、ハッシュが一致するか、`validateAssignment` を通るかを確かめる。どちらかが駄目なら `error` を送って止める。
- `move` は `ply`（何手目か）で順番と重複を判定する。自分の局面の手数 + 1 と一致しないものは、再送なら捨て、飛んでいれば `sync` を求める。
- 相手の手番のあいだは、自分の盤は操作できない。

## 5. 切断と再開

- 対局の状態は役割ごとに `localStorage` の `sanju-shogi:online:<roomKey>:host` / `:guest` に保存する。中身は、役割、自分の色、層数、自分の配置と salt（配置中のみ）、公開後の両者の配置、棋譜、結果。旧形式 `sanju-shogi:online:<roomKey>` は記録された役割のキーへ移行し、新形式の保存があればそちらを優先する。
- Web Locks が使える環境では、タブが `sanju-shogi:<roomKey>:<role>` を排他的に保持する。作成時は host を確保する。リンクを開いたときは host の保存があれば host を試し、別タブが保持していれば guest を試す。host の保存がなければ guest のみを試す。いずれも `ifAvailable: true` とし、空きがなければ別タブで開いている旨を表示する。退出・ページ退避・接続準備の失敗時に解放する。Web Locks がない環境では保存済みの役割を復元する従来の動作とする。
- 相手との接続が切れたら「相手との接続が切れました。相手がリンクを開き直すと再開します」と表示して待つ。
- 再接続したら、互いに `SyncState`（両者の配置、棋譜、結果）を送り合う。一方の棋譜がもう一方の先頭部分と一致していれば、長いほうに合わせる（`core` で合法か確かめながら）。一致しなければ「対局の記録が食い違っています」と表示して止める。
- 配置中に切れた場合は、確定済みのハッシュと自分の配置を保存しておき、再接続後にその続きから進める。

## 6. エラー表示

| 状況 | 表示 |
|---|---|
| 20 秒たっても相手が見つからない（相手側） | 「部屋が見つかりません。リンクが正しいか、相手が待機画面を開いているか確認してください。ネットワークによっては接続できないことがあります」 |
| リレーに一つも接続できない | 「接続の仲介サーバーにつながりません」 |
| `protocol` の不一致 | 「相手のアプリのバージョンが違います。ページを再読み込みしてください」 |
| ハッシュ不一致・不正な手 | 「対局の記録が食い違ったため中断しました」 |
| 同じ役割どうしの hello | 「同じ役割の端末どうしがつながりました。招待リンクは作成者以外の人が開いてください」 |
| このブラウザ内で役割のロックを確保できない | 「この部屋はこのブラウザの別のタブで開かれています」 |
| 3 人目 | 「この部屋は満員です」 |

## 7. 構成

```
src/net/
  protocol.ts    メッセージの型と検証、コミットのハッシュ、SyncState の突き合わせ（純粋関数）
  roomKey.ts     roomKey の生成、リンクの組み立てと読み取り、部屋名の導出
  transport.ts   Transport インターフェースと Trystero 実装（動的 import）
  memoryTransport.ts  テスト用の、つながった 2 つの偽 Transport
  session.ts     OnlineSession：Game と Transport をつなぐ状態機械
  storage.ts     部屋ごとの保存と読み込み
  roleLock.ts    タブごとの役割の排他保持（Web Locks、テスト用に注入可能）
src/ui/
  online.ts      部屋を作る・待機・接続中・エラーの画面
  app.ts         既存の配置・対局画面に「オンライン」の分岐（交代画面なし、相手番は操作不可、待ったの承認）
```

```ts
export interface Transport {
  send(msg: NetMessage): void;
  onMessage(fn: (msg: unknown) => void): void;
  onPeerJoin(fn: () => void): void;
  onPeerLeave(fn: () => void): void;
  leave(): void;
}
```

- `OnlineSession` は Transport だけに依存し、DOM にも Trystero にも依存しない。テストは偽 Transport の組で行う。
- Trystero はオンライン対戦を始めたときに動的 import する（ローカル対戦の読み込みは増やさない）。
- 2 人目以降の peer が来たら、最初の相手以外には `full` を返して無視する。

## 8. テストと確認

- **Vitest**: 偽 Transport の組で、接続 → 色の決定 → 配置のコミットと公開 → 数手 → 投了まで。ハッシュ不一致での中断、不正な手での中断、`ply` の重複と欠落、待ったの承認と拒否、切断中の手の保存と再接続後の突き合わせ（一致・不一致）、3 人目への `full`、形の違うメッセージを捨てること。
- **ブラウザ**: 同じブラウザの 2 つのタブで、本物の Nostr リレー経由で 1 局を通す。片方を再読み込みして続きから再開できることも確かめる。

## 9. 限界（README にも書く）

- 会社のネットワークや一部のモバイル回線では、P2P で直接つながらないことがある（TURN を使わないため）。
- 公開リレーの状態によっては、つながるまで時間がかかったり、つながらなかったりする。
- 相手がブラウザ側のコードを改造すれば、ずるは防げない。コミット・リビールで防げるのは、相手の配置を見てから自分の配置を変えることだけ。


## 10. N4〜N6 の実装メモ（2026-11-02）

- 使用パッケージは `@trystero-p2p/nostr@0.26.0`。インストール済み README と型定義を確認した。`joinRoom(config, roomId)` は同期で Room を返す。`makeAction('msg')` は `{ send, onMessage, … }` を返し、送信は `send(message, { target: peerId })`、受信は `onMessage = (message, { peerId }) => …`。参加・退出は `room.onPeerJoin` / `room.onPeerLeave` への代入、`room.leave()` は Promise。Transport の公開 API は段階1のまま。
- 最初の peer だけに対局メッセージを送る。追加 peer には宛先を指定して `full` を返し、その peer の受信内容と退出通知は対局に渡さない。相手の再読み込みで peer ID が変わるため、元の peer の退出後は新しい接続を受け付ける。
- 20秒経過時、参加側で peer がなければ部屋未発見の案内を出す。`getRelaySockets()` の WebSocket が一つも OPEN でなければ、作成者にも仲介サーバー未接続の案内を出す。WebSocket が OPEN でもリレーの仲介受理までは保証できず、その場合は部屋未発見の案内となる。案内後も待機を続け、遅れて接続した場合に進む。接続済みの P2P はリレーの切断だけでは止めない。
- UI は `OnlineSession` の通知ごとに `session.game` を読み直す。配置中の描画は自分の Placement のみで、相手の commit は文字だけで通知する。確定後・相手番・待ったへの回答待ち・切断中・エラー中は該当する盤の操作を止める。
- 起動時とハッシュ変更時に招待リンクを読む。保存済みの role / 層数を復元し、公開済みの対局は再公開演出をせず表示する。BFCache の退避時は描画と接続を破棄し、復帰時は URL に残る同じ部屋へ再接続する。「タイトルへ」は部屋のハッシュを消して退出するが、再開用の保存は残す。
- 未確定の配置案は保存しない。確定済みの自分の配置と salt は段階1の部屋保存で再開する。保存禁止環境では再開を保証できない。ローカル対戦の保存キーにはオンラインの状態を書かない。
- オンライン UI / CSS と Trystero は動的 import。初期 JS を増やさないため、共通の対局パネル・視点ツールバー・選択ダイアログも盤の画面で遅延読み込みする。
- Transport のモックと jsdom + MemoryTransport で画面・操作・再開・後始末を検証。実 Nostr リレー経由での2タブ対戦と再読み込みは別途ブラウザ確認が必要。
