# 三重将棋（sanju-shogi）設計書

- 日付: 2026-10-31
- 状態: 暫定（レビュー待ち）
- リポジトリ: `torifo/sanju-shogi-game`（GitHub Pages: `https://torifo.github.io/sanju-shogi-game/`）
- ローカル: `~/dev/game/sanju-shogi`

## 1. 概要

9×9 の将棋盤を 3 層に重ねた立体将棋。駒は通常の将棋と同じ 40 枚（各 20 枚）。
初期配置の「筋・段」は本将棋と同じで、**各駒をどの層に置くかだけを各プレイヤーが決める**。
配置は互いに見えない状態で決め、同時に公開してから対局を始める。

静的サイトとして GitHub Pages で公開する。サーバーは持たない。

### 決まっていること

| 項目 | 決定 |
|---|---|
| 盤 | 9 筋 × 9 段 × 3 層（下層・中層・上層） |
| 縦の動き | 平面の動き＋層 ±1（§3） |
| 対戦 | ローカル 2 人対戦（1 台で交互に指す）。CPU は次の段階 |
| 初期配置 | 秘密配置 → 同時公開 |
| 技術 | Vite + TypeScript + Three.js、テストは Vitest |
| 次の拡張 | モード切り替えで 9×9×9 の立方体（§9） |

### やらないこと（初版）

CPU 対戦、オンライン対戦、持ち時間、入玉宣言、棋譜ファイルの読み込み。

## 2. 用語と座標

- **筋** x = 1..9（右から左。本将棋と同じ）
- **段** y = 1..9（先手から見て奥が 1）
- **層** z = 0..L-1（0 = 下層。初版は L = 3）

「段」は将棋用語として行のことを指すため、立体の高さは常に「層」と呼ぶ（作品名の「三重」は層の数を表す）。
盤の寸法は `BoardConfig { files: 9, ranks: 9, layers: L }` という設定値で持ち、ルールのコードに 3 を直接書かない。

## 3. 駒の動き

本将棋の各駒の動きを「平面の移動ベクトル (dx, dy)」の集合として定義し、それを次の規則で立体に広げる。

### 3.1 一歩ずつ動く駒（玉・金・銀・歩・成駒、竜と馬の一歩部分）

平面ベクトル (dx, dy) ごとに、移動先は (x+dx, y+dy, z+dz)、ただし dz ∈ {-1, 0, +1}。
つまり本来の動きをしながら、同時に上下 1 層まで移れる。

### 3.2 桂

(±1, 前へ 2) に dz ∈ {-1, 0, +1} を組み合わせる。途中の駒は飛び越える。

### 3.3 走る駒（飛・角・香、竜の飛部分、馬の角部分）

平面の方向 (dx, dy) と dz ∈ {-1, 0, +1} の組ごとに、k 歩目の位置を (x+k·dx, y+k·dy, z+k·dz) として進む。
盤の外に出るか駒に当たったところで止まる（敵の駒なら取れる）。
dz ≠ 0 の方向は層の数で長さが決まる（3 層なら最長 2 マス）。

### 3.4 真上・真下への移動

平面で**真横 (±1, 0) に動ける駒**だけが、平面で動かずに真上・真下 (0, 0, ±1) へも動ける。

- 一歩ずつ：玉・金・と・成香・成桂・成銀・馬
- 走る：飛・竜（縦方向に盤の端まで）

銀・桂・香・角・歩は真上・真下へは動けない。

### 3.5 取り・持ち駒・打ち

- 取った駒は成りを戻して持ち駒になる。
- 持ち駒は**空いているどの層のどのマスにも**打てる。打った駒は成っていない状態。
- **二歩**：同じ層の同じ筋 (x, z) に、成っていない自分の歩を 2 枚置けない。別の層なら同じ筋でもよい。
- **行き所のない駒**：歩・香は 1 段目に、桂は 1〜2 段目に打てない（先手から見た場合。層は問わない）。
- **打ち歩詰め**は禁止。

### 3.6 成り

- 敵陣 = 相手側の 3 段（先手なら 1〜3 段）。**層は問わない**。
- 敵陣に入る・敵陣から出る・敵陣の中で動く、のいずれかで成るかどうかを選べる。
- 行き所がなくなる移動（歩・香が 1 段目、桂が 1〜2 段目）では必ず成る。

### 3.7 勝敗

- 自玉に王手がかかったままになる手は指せない。
- 王手を解除できなければ詰みで負け。指せる手が一つもないときも、本将棋にならって手番側の負け。
- 投了できる。
- **千日手**：同じ局面（盤・持ち駒・手番）が 4 回現れたら引き分け。それが連続王手によるものなら、王手をかけていた側の負け。
- 「待った」はローカル対戦の便利機能として 1 手ずつ戻せる。

## 4. 初期配置（秘密配置 → 同時公開）

### 4.1 ルール

- 20 枚の駒の筋・段は本将棋の初期位置で固定。
- 各駒の層を 0..L-1 から自由に選ぶ。制約はない（同じ筋に高さの違う駒が並ぶのも、全部を上層に置くのもよい）。
- 最初は全駒が中層。「全部を中層」「ランダム」のボタンを置く。

### 4.2 流れ（1 台で遊ぶ場合）

```
タイトル（新規対局 / 続きから）
  → 交代画面「先手の番です。後手は画面を見ないでください」
  → 先手の配置（自分の駒だけ表示）→ 確定
  → 交代画面「後手に渡してください」
  → 後手の配置（先手の配置は表示しない）→ 確定
  → 公開演出（両者の駒が一斉に各層へ上がる）
  → 対局開始（先手から指す）
```

交代画面はタップするまで盤を描かない。配置中は相手の駒を一切描かない（見た目を薄くするだけではなく、データとしても画面に出さない）。

### 4.3 配置の操作

駒をクリックして選び、`上 / 中 / 下` ボタン、数字キー 1〜3、または上下のドラッグで層を変える。
筋ごと・駒の種類ごとにまとめて変える操作は、使ってみて要るとわかってから足す。

## 5. 画面と操作

### 5.1 3D 表示（Three.js）

- 半透明の盤を 3 枚、間を空けて重ねる。盤ごとに格子線と段・筋の目盛りを描く。
- 駒は五角形の板。駒の字は Canvas に描いてテクスチャにする（画像は用意しない）。後手の駒は 180° 回す。
- 駒から下層へ細い影の線を落とし、どの層にいるか読みやすくする。
- カメラは OrbitControls で回せる。視点の切り替えボタン：斜め / 真上 / 横。
- **層に注目する表示**：層を一つ選ぶと他の層を薄くする。層の間隔を広げるボタンも置く。

### 5.2 展開図（ミニマップ）

画面の端に 3 層を平らな盤として並べて描く。**3D 表示と同じ操作がここでもできる**（駒を選ぶ・指す・打つ）。
立体の読み違いを防ぐ補助と、WebGL が使えない環境での代わりを兼ねる。

### 5.3 対局の操作

- 駒を選ぶと、指せるマスを全層にわたって強調表示する（3D と展開図の両方）。
- 持ち駒は盤の両脇の DOM パネル。持ち駒を選ぶと打てる空きマスを強調表示する。
- 成れる手では「成る / 成らない」を聞く。
- 王手・詰み・千日手はバナーで知らせる。
- 棋譜は右側の一覧に出す。表記は `▲7六歩 中→上`（移動先の筋段・駒・移動元と移動先の層）、打ちは `▲5五角打 上`。

### 5.4 対応環境

PC（マウス）とスマホ（タッチ）。スマホでは展開図を折りたたみ式にする。
表示の確認は Chrome を主とし、Safari でも操作できることを確かめる。

## 6. 構成

ルールは描画から切り離した純粋な TypeScript にする。CPU を足すときは、このルール部分をそのまま Web Worker に載せる。

```
src/
  core/            ルール（DOM・Three.js に依存しない）
    types.ts       Color, PieceType, Piece, Square{x,y,z}, Move（移動/打ち, 成り）
    config.ts      BoardConfig と盤の種類（SANJU = 9×9×3、将来 CUBE = 9×9×9）
    pieces.ts      駒ごとの平面ベクトル・走るかどうか・真上真下に動けるか・成り先
    position.ts    局面（マス配列 index = x + y·9 + z·81、持ち駒、手番）、手の適用と取り消し
    movegen.ts     指し手の生成、利きの判定
    rules.ts       王手の判定、合法手の絞り込み、打ちの制約、打ち歩詰め、勝敗
    setup.ts       層の割り当て → 初期局面、割り当ての検証
    hash.ts        Zobrist ハッシュ（千日手の判定用）
    notation.ts    棋譜の表記
    serialize.ts   局面・対局の文字列化（保存と再開、テスト用）
    game.ts        対局の進行（配置→公開→対局→終局）、棋譜、待った
  render/          Three.js
    scene.ts  boardMesh.ts  pieceMesh.ts  highlights.ts  picking.ts  camera.ts
  ui/              DOM
    app.ts（画面の切り替え） handoff.ts  placement.ts  hands.ts
    promotion.ts  log.ts  minimap.ts  banner.ts
  main.ts
tests/             Vitest（core のみ）
```

### 6.1 データの流れ

`ui` が入力（クリック・タップ）を受け取り、`core/game.ts` に手を渡す。
`game` が合法かどうかを判定して局面を進め、変化を通知する。
`render` と `ui` は通知を受けて描き直す。`render` と `ui` は局面を直接書き換えない。

### 6.2 保存

対局中の状態は手番ごとに `localStorage` に保存し、タイトルの「続きから」で再開できる。
**配置中の状態は保存しない**（相手の秘密配置が残らないようにする）。
読み込めないデータは捨てて新しく始める。`localStorage` が使えない環境でも遊べるようにする。

## 7. エラーと例外

- WebGL が使えない：その旨を表示し、展開図だけで遊べるようにする。
- 保存データが壊れている：捨てて新規対局にする。
- 不正な手：UI は合法手しか選べないので通常は起きない。起きたら `game` が拒否して局面を変えない。

## 8. テストと確認

- **Vitest（core）**
  - 駒ごとの動き（層 ±1、真上真下、端での打ち切り、dz ≠ 0 の走りが駒に当たって止まる）
  - 打ちの制約（同じ層での二歩、別の層の同じ筋は打てる、行き所、打ち歩詰め）
  - 成り（敵陣の出入り、強制の成り）
  - 王手・詰み・千日手・連続王手の千日手
  - 層の数を 3 と 9 の両方にしてテストを流し、立方体モードでも壊れないことを担保する
- **ブラウザでの確認**：配置 → 交代 → 公開 → 数手指す → 詰みまで、を実際に操作して確かめる。

## 9. 次の拡張：9×9×9 モード

- タイトルにモードの切り替え（三重 / 立方）を置く。中身は `BoardConfig.layers` を 3 から 9 に変えるだけで動くようにしておく。
- ルールの変更はない（敵陣は段で決まる、配置の高さは 0..8、走る駒の縦の距離が伸びる）。
- 描画で変わるのは層の間隔、カメラの初期位置、展開図のスクロールのみ、という状態を目指す。
- 9 層で 40 枚だと駒が出会いにくくなるので、遊びやすさはその段階で調整する。
