# 三重将棋

9×9×3 層の盤で、1 台の端末での交代対局と招待リンクによるオンライン対局ができる立体将棋です。Vite + TypeScript + Three.js を使った GitHub Pages 対応の静的サイトです。

## 遊び方

1. 「新規対局」から、先手・後手が交代で秘密配置を行います。相手は画面を見ず、交代画面で端末を渡してください。駒の筋と段は本将棋の初期位置で固定し、各 20 枚を置く層だけを選びます。
2. 両者が配置を確定すると同時に公開し、先手から対局を始めます。
3. 駒や持ち駒を選び、緑色の合法手のマスを選んで指します。成れる手では成るかどうかを選びます。相手の玉を詰ませれば勝ちです。

駒は本将棋の平面の動きに、上下の層への動きを組み合わせます。

- 一歩動く駒と桂は、本来の移動と同時に上下 1 層まで移れます。桂は途中の駒を飛び越えます。
- 飛・角・香などの走る動きは、同じ層を進むか、1 マス進むごとに上または下へ 1 層ずつ進みます。途中の駒を飛び越えられません。
- 平面で真横へ動ける駒は、真上・真下にも動けます。玉・金・金と同じ動きの成駒・馬は 1 層、飛・竜は途中に駒がなければ何層でも移れます。銀・桂・香・角・歩は真上・真下だけの移動はできません。
- 取った駒は成りを戻して持ち駒になり、空きマスに打てます。二歩は**同じ層の同じ筋**で判定し、別の層の同じ筋には歩を打てます。行き所のない駒の打ち・打ち歩詰めは禁止です。
- 敵陣は**相手側の奥の 3 段**で、層は問いません。敵陣への出入りや敵陣内の移動で成れます。行き所がなくなる手では必ず成ります。
- 王手を放置する手は指せません。同じ局面が 4 回現れると千日手で引き分け、連続王手による千日手は王手をかけた側の負けです。

## 操作と保存

- 3D の盤と、各層を並べた展開図の両方から、配置・移動・持ち駒の打ちを操作できます。スマホでは展開図を開いて使えます。
- 3D はドラッグで回転し、ホイールやピンチで拡大・縮小します。「視点」で斜め・真上・横を切り替え、「注目」で特定の層以外を薄くし、「間隔を広げる」で盤の重なりを見やすくします。
- 秘密配置では駒を選び、層のボタン・数字キー（1＝下、2＝中、3＝上）・上下のドラッグで層を変えます。「全部を中層」「ランダム」も使えます。
- 「待った（一手戻す）」で 1 手戻せます。「投了」は確認後に対局を終了します。
- 公開後の対局はブラウザのローカルストレージへ自動保存し、タイトルの「続きから」で再開できます。保存領域を利用できない場合は画面に知らせます。ローカル対戦の秘密配置は保存しません。ローカル対戦でページを離れて戻る場合はタイトルに戻ります。「新規対局」は前の保存を消します。
- WebGL 非対応、3D の読み込み・初期化失敗、WebGL コンテキスト喪失時は、展開図だけで配置から対局まで遊べます。

## オンライン対戦（招待リンク）

1. タイトルの「オンライン対戦」から、自分の先手・後手・ランダムを選び「部屋を作る」を押します。
2. 待機画面の招待リンクをコピー（対応端末では「共有」も利用可能）して相手に送ります。部屋を作った側は画面を開いたまま待ちます。
3. 相手がリンクを開くと自動的に接続し、それぞれの端末で秘密配置を行います。配置中に見えるのは自分の駒だけです。相手の確定は文字で表示し、両者の確定と照合が完了すると同時に公開して対局を始めます。
4. 自分の手番だけ盤を操作できます。「待ったを申し込む」は相手の承認後に一手戻します。「投了」は自分の色の投了として扱い、確認後に終局します。
5. 切断すると操作を止めて盤を残します。**同じ端末・ブラウザで同じリンクを開き直す**と、役割と保存済みの配置・棋譜から再接続します。作成者も同じリンクで作成者として戻れます。未確定の配置案は保存せず、確定済みの自分の配置と salt は公開まで保存します。
6. 終局後は「タイトルへ」で戻ります。この操作で接続を離れ、URL の部屋情報を消します。保存済みの部屋は残るので、再開用のリンクは別途保管してください。ローカル対戦の保存とは別に管理します。

接続できない場合は、リンク全体が正しいか、相手が画面を開いているかを確認してください。参加側は20秒経っても相手が見つからないと案内を表示します。案内の後も接続を試み、相手が見つかれば進みます。部屋は2人用で、3人目は満員と表示します。

### オンライン対戦の仕組みと限界

- `@trystero-p2p/nostr` の公開 Nostr リレーで接続を仲介し、指し手は WebRTC の P2P 通信で送ります。TURN 中継は使わないため、会社のネットワークや一部のモバイル回線では接続できないことがあります。
- 公開リレーの状態によって接続に時間がかかったり、つながらなかったりします。リレーの WebSocket がすべて未接続の場合は仲介サーバーの案内を表示します。WebSocket の接続だけでは、リレーが仲介を受け付けたことまでは保証できません。
- 保存にはブラウザの localStorage を使います。保存を禁止している環境や保存データを消した場合、再開を保証できません。別の端末へ自動では引き継げません。
- 招待リンクを知る人が参加できます。公開の場所にリンクを載せないでください。
- コミット・リビールは、相手の配置を見てから自分の配置を変更することを防ぎます。改造クライアントによるずる全般には対応しません。友達同士で遊ぶ前提です。
- Trystero とオンライン処理はオンライン画面に入ってから動的に読み込みます。

CPU 対戦・持ち時間には対応していません。詳しいルールは[設計書](docs/superpowers/specs/2026-10-31-sanju-shogi-design.md)と[オンライン設計書](docs/superpowers/specs/2026-11-02-online-play-design.md)を参照してください。

## 開発

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npm run preview
```

Node.js 22.12 以上を使用します。`dev` は開発サーバー、`preview` はビルドした `dist/` の確認用サーバーです。`typecheck` は型検査、`test` は Vitest、`build` は型検査と本番ビルドを行います。

## GitHub Pages への公開

[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) が `main` への push または手動実行でテスト・ビルドを行い、`dist/` を Pages に公開します。リポジトリの Settings → Pages → Source は GitHub Actions を選びます。

Vite の公開パスは環境変数 `BASE_PATH` で指定します。ワークフローでは `/sanju-shogi-game/` を設定しています。別のリポジトリ名で公開する場合は、その値も変更してください。ローカルで同じパスを確認する場合は次のように実行します。

```sh
BASE_PATH=/sanju-shogi-game/ npm run build
npm run preview
```

`BASE_PATH` を省略した場合は `/` が使われます。
