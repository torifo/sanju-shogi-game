# 三重将棋

9×9×3 層の盤を 1 台の端末で交代して指す立体将棋で、Vite + TypeScript + Three.js を使った GitHub Pages 対応の静的サイトです。

## 遊び方

1. 「新規対局」から、先手・後手が交代で秘密配置を行います。相手は画面を見ず、交代画面で端末を渡してください。駒の筋と段は本将棋の初期位置で固定し、各 20 枚を置く層だけを選びます。
2. 両者が配置を確定すると同時に公開し、先手から対局を始めます。
3. 駒や持ち駒を選び、緑色の合法手のマスを選んで指します。成れる手では成るかどうかを選びます。相手の玉を詰ませれば勝ちです。

駒は本将棋の平面の動きに、上下の層への動きを組み合わせます。

- 一歩動く駒と桂は、本来の移動と同時に上下 1 層まで移れます。桂は途中の駒を飛び越えます。
- 飛・角・香などの走る動きは、同じ層を進むか、1 マス進むごとに上または下へ 1 層ずつ進みます。途中の駒を飛び越えられません。
- 平面で真横へ動ける駒は、真上・真下にも動けます。玉・金・金と同じ動きの成駒・馬は 1 層、飛・竜は途中に駒がなければ何層でも移れます。銀・桂・香・角・歩は真上・真下だけの移動はできません。
- 取った駒は成りを戻して持ち駒になり、空きマスに打てます。二歩は**同じ層の同じ筋**で判定し、別の層の同じ筋には歩を打てます。行き所のない駒の打ち・打ち歩詰めは禁止です。
- 敵陣は**相手側の奥の 3 段**で、層は問いません。敵陣への出入りや敵陣内の移動で成れます。行き所がなくなる手では必ず成ります。
- 王手を放置する手は指せません。同じ局面が 4 回現れると千日手で引き分け、連続王手による千日手は王手をかけた側の負けです。

## 操作と保存

- 3D の盤と、各層を並べた展開図の両方から、配置・移動・持ち駒の打ちを操作できます。スマホでは展開図を開いて使えます。
- 3D はドラッグで回転し、ホイールやピンチで拡大・縮小します。「視点」で斜め・真上・横を切り替え、「注目」で特定の層以外を薄くし、「間隔を広げる」で盤の重なりを見やすくします。
- 秘密配置では駒を選び、層のボタン・数字キー（1＝下、2＝中、3＝上）・上下のドラッグで層を変えます。「全部を中層」「ランダム」も使えます。
- 「待った（一手戻す）」で 1 手戻せます。「投了」は確認後に対局を終了します。
- 公開後の対局はブラウザのローカルストレージへ自動保存し、タイトルの「続きから」で再開できます。保存領域を利用できない場合は画面に知らせます。秘密配置は保存しません。ページを離れて戻る場合はタイトルに戻ります。「新規対局」は前の保存を消します。
- WebGL 非対応、3D の読み込み・初期化失敗、WebGL コンテキスト喪失時は、展開図だけで配置から対局まで遊べます。

CPU 対戦・オンライン対戦・持ち時間には対応していません。詳しいルールは[設計書](docs/superpowers/specs/2026-10-31-sanju-shogi-design.md)を参照してください。

## 開発

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npm run preview
```

Node.js 22.12 以上を使用します。`dev` は開発サーバー、`preview` はビルドした `dist/` の確認用サーバーです。`typecheck` は型検査、`test` は Vitest、`build` は型検査と本番ビルドを行います。

## GitHub Pages への公開

[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) が `main` への push または手動実行でテスト・ビルドを行い、`dist/` を Pages に公開します。リポジトリの Settings → Pages → Source は GitHub Actions を選びます。

Vite の公開パスは環境変数 `BASE_PATH` で指定します。ワークフローでは `/sanju-shogi-game/` を設定しています。別のリポジトリ名で公開する場合は、その値も変更してください。ローカルで同じパスを確認する場合は次のように実行します。

```sh
BASE_PATH=/sanju-shogi-game/ npm run build
npm run preview
```

`BASE_PATH` を省略した場合は `/` が使われます。
